# i27 Helpdesk UI

Next.js and TypeScript frontend for the i27 Helpdesk microservices application.

The UI provides role-based helpdesk workflows and is containerized and deployed to Amazon EKS as part of the AWS DevOps implementation.

## Application Flow

```text
Browser
   |
   v
Application Load Balancer
   |
   +--> UI routes --------> Next.js UI
   |
   +--> API routes -------> API Gateway
                              |
                              v
                       Backend Services
```

The broader AWS infrastructure and platform implementation is documented in:

[i27-helpdesk-aws-infra](https://github.com/Manojsabbithi/i27-helpdesk-aws-infra)

## Same-Origin API Routing

The active API client uses relative request URLs rather than embedding an environment-specific Application Load Balancer hostname in the frontend image.

```typescript
const api = axios.create();
```

This allows both the UI and API traffic to use the same browser origin, while the AWS Application Load Balancer routes requests to the appropriate Kubernetes service.

Authenticated requests attach the bearer token through the Axios request interceptor, while login requests are excluded from that behavior.

This design avoids rebuilding the frontend whenever the dynamically assigned AWS load-balancer hostname changes.

## AWS CI/CD Pipeline

The AWS-specific Jenkins pipeline is defined in `Jenkinsfile.aws`.

```text
Checkout
   |
   v
UI Tests & Coverage
   |
   v
SonarQube Analysis
   |
   v
Quality Gate
   |
   v
Docker Build
   |
   v
Amazon ECR Push
   |
   v
ECR Image Verification
   |
   v
Amazon EKS Deployment
```

Jest generates LCOV coverage during CI, and the SonarQube quality gate must pass before the container image is built and deployed.

## Kubernetes Deployment

AWS Kubernetes manifests are stored under `k8s/aws/`.

The deployment includes:

- readiness and liveness probes
- CPU and memory requests and limits
- image replacement using the commit-derived ECR image tag generated by Jenkins
- rollout verification after deployment
- deployed-image verification against the expected ECR image
- ClusterIP service routing port `80` to container port `3000`

## Container

The Dockerfile uses a multi-stage Node.js 18 Alpine build.

The application runs on port `3000` inside the container.

## Local Development

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Build the production application:

```bash
npm run build
```

## Project Context

This repository originated from the i27Academy Helpdesk application and is used here as part of an independent AWS DevOps portfolio implementation.

The AWS-focused work includes same-origin API routing, automated UI testing and coverage, SonarQube quality gates, Docker containerization, Amazon ECR publishing, Amazon EKS deployment, health probes, resource controls, and automated rollout verification.
